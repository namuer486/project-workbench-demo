# 项目工作台制作流程

_把项目分散资料变成一个可交付、可部署、可持续同步的自包含 HTML 工作台。核心是「数据与模板分离 + 口径单点定义」：数据管线产出 JSON，模板用占位符注入，标签与分类只在一处定义、多处复用。_

**附件（复现的权威依据，必须照用）**

| 文件 | 作用 |
|---|---|
| `references/workbench.css` | **真品样式表（457 行，逐字节抽取自最终成品）**。整体内联进 `<style>` 即得到完全一致的视觉 |
| `references/ui-spec.md` | 设计令牌、布局尺寸、组件清单、动效规格、UI 自检清单 |
| `references/panels-ipd-dimensions.md` | 七板块 × IPD 环节 × 六大要素的完整对应表 + 联动数据流 |
| `references/template-lint.md` | 模板静默失效的两道 lint（行尾拼接、顶层逗号截断） |

## 适用场景

- 策划/PM 手头有 Excel 问题表、会议纪要、版本总结、用研报告，想整合成一个网页工作台。
- 需要问题提交（可标"未解决"后续补交）、周期总览、数据洞察、关系图谱，但不想搭后端。
- 数据源会周期性更新，需要低成本反复同步。
- 需要按 IPD 阶段定位项目、按统一的「衡量标签」口径统计与归因。

## 核心纪律

1. **数据与模板分离**：模板只留 `const KB_DATA = __KB_DATA__;`，数据一律走 JSON 注入；数据源更新 = 重跑管线 + 重新注入，绝不手改 HTML 里的数据。
2. **自包含单文件**：零外部依赖（不引 CDN、不引图表库，图表用内联 SVG/Canvas 手写），双击即开、可直接部署。
3. **口径单点定义**：分类/标签只存一份（`dimensions[]` / 关键词规则表），其余地方全部由它派生；**任何两处出现同一份标签清单就是缺陷**。
4. **file:// 环境兜底**：`localStorage` 在 file:// 或隐私模式可能抛异常，全部读写走 `safeStorage`（try/catch + 内存兜底）。
5. **分析类数据与流水数据分仓**：流水（表格行）随数据源覆盖；分析提炼（总结条目、纪要、标签体系、用研结论）独立存放，重同步时原样保留。
6. **凡筛选必绑事件**：每个下拉/卡片筛选都要有 `change`/`click` 触发重渲染（历史最高频 bug）。
7. **先烟测再交付**：`node --check` + jsdom 冒烟测试全视图无错误 + 关键数字断言，才允许部署。

## 制作步骤

### 步骤 1 · 需求分析（动手前必须确认的 6 件事）
1. **数据源清单**：哪些文件、各承载什么（流水问题 / 纪要 / 版本定位 / 用研结论与截图）。
2. **板块清单**：默认七大板块（见附件二），按需增删功能模块（板块骨架不要动）。
3. **衡量标签体系**：是否已有权威标签（如用研六维）？没有则先用分类桶替代，并注明待补。
4. **分层标准**：什么算"高价值/有通用性"，什么归"次级关联分析库"。
5. **版本语义**：是否有版本大类（当前版本优先 + 旧版本折叠），划分依据（日期阈值）。
6. **方法论框架**：总结性条目按什么结构写（本项目为四段式：目标 → KSF → 解决方案 → 复盘反思）。
> 纪律：先跟用户确认以上假设再动手，返工成本远高于确认成本。

### 步骤 2 · 数据管线（解析 → 富化 → 落盘）
1. **解析器**：xlsx/docx 都是 zip，`zipfile + re` 零依赖解析。
   - xlsx：sharedStrings 共享表、inlineStr、自闭合单元格 `<c r="A1"/>`、Excel 日期序列号（`date(1899,12,30)+n天`）。
   - docx：**`<w:t>` 必须精确匹配 `<w:t(?=[ >])[^>]*>`**，否则会误吞 `<w:tblPr>` 把 XML 当正文；按 `<w:tbl>|<w:p>` 顺序遍历以保留表格。
   - **必须解码 HTML 实体**：单元格换行会以 `&#10;` 存进 sharedStrings，不解码会显示成字面量（实测 240 条里 71 条中招）。
2. **图片资产**：用研/截图的图片先压缩再内嵌。Pillow 装到隔离 venv（`python -m venv <env>` → `<env>/Scripts/pip install Pillow`），按宽 820px、JPEG q=78 压缩（典型 440KB → 46KB），转 base64 写入 JSON。
3. **富化派生字段**：分类（关键词桶，**要设打分下限阈值**）、状态归一（已完成/完成→已解决）、优先级归一、周归属（周映射表）、版本归属（日期阈值）、**衡量标签 `dims[]`（关键词优先级规则 + 所属主题兜底映射，允许多标签 ≤2）**。
4. **产出 `kb_data.json`**：
   ```json
   {
     "meta": {"generated":"…","project":"…","version":"…"},
     "versionSummary": {"positioning":"…","principle":"…","period":"…"},
     "categories": ["…"],
     "items": [{"id","no","title","solution","owner","priorityTier","statusNorm","category","topic","dims","date","week","version","layer"}],
     "meetings": [{"date","week","title","points":[]}],
     "projectIssues": [{"id","date","title","dims","goal","ksf":[],"solution","review","relatedTopics":[]}],
     "topics": [{"topic","title","desc","keys":[],"count","unresolved","dims","relatedPi":[]}],
     "dimensions": [{"key","icon","color","def","passRate","dist":[],"score","weighted","good","bad","advice","relatedTopics":[],"relatedPi":[],"itemCount","unresolved"}],
     "dimensionMeta": {"source","scale","distLabels":[],"conclusion"},
     "urReport": {"title","subtitle","meta":[],"conclusion","retention":{},"churn":{},"advices":[],"images":[{"key","src","title","desc","hotspots":[{"dim","kind","text","x","y"}]}]},
     "defectSummary": {"total","resolved","unresolved"}
   }
   ```
   分析类字段（meetings / projectIssues / topics / dimensions / urReport）与流水 items 分开存放，重同步时保留。
5. **建立双向关联**：主题 ↔ 项目问题（LINK 表 + 反向索引），维度 → 主题/项目问题。前端只做「设状态 → 切视图 → 目标视图读状态」。

### 步骤 3 · 结构搭建（模板与七大板块）
1. 单文件模板：内联 `references/workbench.css`，占位符 `__KB_DATA__`，生成时字符串替换。
2. 严格按 `references/panels-ipd-dimensions.md` 搭七个板块的 DOM 骨架（导航分「核心 / 过程 / 综合」三组，默认落在项目提炼）。
3. 顶栏：标题 + 面包屑 + 全局搜索（260px，输入即跳数据洞察并筛选）+ 日期。

### 步骤 4 · 功能实现（逐板块，规格见附件一/二）
- **项目提炼**：IPD 横幅 → 4 统计卡 → 六维标签卡（点击筛维度）→ 通用性总结条目（带维度 chips、关联项目问题、查看明细）→ 用研定位图（百分比坐标标签）→ 用研报告要点（结论 + 留存/流失 + 8 条建议按维度归类）。
- **时间轴**：横向滚动 + 节点上下交替（`grid-template-rows:1fr auto 1fr` 让圆点居中）；卡片带版本徽标/六维 chips/分提炼主题 chips；点击开四段式详情。
- **提交**：四段式表单 + **六维标签必填可多选**；未解决可补交；编辑弹窗可改标签/日期/来源。
- **每周总览**：周选择器按版本分组 + 本周统计 + 纪要 + 分类分布 + 问题清单。
- **图谱**：Canvas 力布局。**节点 >200 时 O(n²) 斥力会卡 20 秒+，必须用 grid-bucket 网格近邻斥力**；六维节点按维度着色为轴心，**选定某维度时轴心收窄为单一维度**；钉在环上的节点存单位向量（`fx=cos(ang)`），半径只在定位时乘一次。
- **数据洞察**：统计卡 + 版本概览 + 状态环形图 + 六维分布条 + 三层问题库（当前版本展开 / 旧版本折叠 / 关联分析库折叠）+ 四类筛选（状态/分类/优先级/**标签**）。
- **AI 接口**（v1.1.0 实测接口，**不要再照抄旧方法名**）：`window.KnowledgeBaseAI.{version, getData, addItem, updateItem, query, getProjectIssues, addProjectIssue, updateProjectIssue, getConfig, setConfig, sync}`。
  - `query(filter)` 的过滤字段是 **`status` / `category` / `priority` / `keyword`**，**不是** `statusNorm` / `priorityTier`（写错会静默返回全量，极易误判为"筛选生效"）。
  - 没有 `getItems` / `getSummary` / `ask` / `on`；条目数用 `getData().length`，项目问题用 `getProjectIssues()`。
  - 未配置 endpoint 时 `sync()` 会**明确抛错**（`未配置 AI 接口端点`），不做静默兜底。
- **全局**：`switchView` **不同步 `location.hash`**（实测 0 处 `location.hash`，无 hash 路由）；导航切换会重置提炼板块的维度/主题筛选状态。

### 步骤 5 · 内容填充（分析提炼）
1. **主题聚类**：关键词表把流水条目打进 15–20 个主题桶（每桶 ≥3 条才算重复问题）。
2. **通用性分层**：高价值 = 重复主题 / 未解决 / 高优先级 / 缺陷；次级 = 一次性微调（操作性信号词 + 短文本 + 已解决 + 一般优先级）→ 关联分析库。
3. **总结条目撰写**：通用化标题 + 规律描述 + 关键点 + 条数/未解决 + 负责人，并按方法论补结构化字段。
4. **标签落到具体问题**：每个维度卡必须写明该维度的具体问题（亮点/不足各一句）；提炼条目与定位图标签都必须给「具体问题」，不允许只贴标签。
5. **人名归一**：别名映射 + 去括号注释 + 多分隔符拆分 + 过滤非人名词；**归一函数只写一处**，各板块都调它，避免「图谱已归一、卡片还是原始写法」。
6. **文案正式化**：标题用名词短语，删掉"类比…"这类解释性副标题。

### 步骤 6 · 验证与部署
1. **语法检查**：提取 `<script>` → `node --check`（只能查语法）。
2. **模板 lint**：跑 `references/template-lint.md` 的两道检查（行尾 `)`/`}`/`]` 后紧跟字符串字面量；`innerHTML =` 顶层逗号截断）。
3. **jsdom 冒烟测试**：mock canvas 2d（Proxy 兜所有 method，`measureText` 返回 `{width}`）、`ResizeObserver`、`scrollIntoView`、`confirm`、`fetch`；过滤 `Not implemented` 噪声。断言：
   - 关键计数与管线输出一致（条目数/分层数/各维度 itemCount/解决率）
   - **口径一致**：维度筛选后的行数 = 该维度 itemCount；图谱轴心节点 = 6（全量）/1（选定）
   - 交互回写：提交→记录+标签写入、补交→状态变更、筛选 change→联动、折叠→展开有内容
   - 联动：提炼→时间轴（含来源提示条、清除关联后回全量）、时间轴 chip→提炼高亮
4. **视觉验证**：agent-browser 起不来（Windows 上 Chrome exit 3 很常见）时用系统 Edge：
   `msedge.exe --headless=new --disable-gpu --no-sandbox --hide-scrollbars --user-data-dir=<临时目录> --window-size=W,H --virtual-time-budget=9000 --screenshot=out.png "file:///…"`；
   模板没有 hash 路由时，**生成临时的默认板块副本**（替换初始化那行 `switchView('x')`）来截非首屏板块，截完即删。
   - 路径含空格要写成 `%20`，中文目录要先 percent-encode；W/H 给窗口尺寸（不是视口），想看清首屏细节就给 ≤1100 的高。
   - 截图前先确认临时副本**确实存在**：文件名对不上时 Edge 会安静地渲染出「未找到文件」页并照样写出 PNG，容易误判为版式问题。
5. **部署**：复制为 `.workbuddy/deploy/index.html` → cloudstudio_deploy（同一目录重复部署，URL 不变）。
6. **线上一致性校验**：`curl -s <shareLink> -o online.html` 后与本地 HTML 比 **md5**（比抽字段更硬），再核对 HTTP 200 与字节数。md5 相同即数字必然一致，不必再逐字段比对。

### 复现踩坑（实测记录，动手前先读）

1. **分类桶必须"加权打分取最高"，不能用"先命中先定"**：宽关键词（如 `提示` / `距离`）会把整表吸进同一个桶——实测 240 条里 48% 落进单一分类。做法是每条关键词给权重、按总分排序取第一；并对"最终不足 3 条的稀薄桶"用**次优候选回填**，否则会出现 `count=0/2` 的空桶而主题列表里缺项。
2. **通用性主题的计数只覆盖高价值层**（`layer!=='minor'`），并且必须**同步让主题筛选排除次级条目**（`filterItems` 里 `i.layer==='minor'` 直接 return false）。只改一处就会出现「条目卡写 36 条、点『查看明细』却出 39 行」。次级条目归「关联分析库」，语义上不属于通用性主题。
3. **同一屏上的同名数字要区分口径前缀**：提炼统计卡「已覆盖问题明细」= 高价值层；数据洞察版本统计卡不含分层；问题库分区标题**不含次级**。实测 `3.0 预备任务` 在统计卡是 72、在问题库列表是 63，必须在列表标题上写明「不含次级」。
4. **数据源缺用研报告时的降级**：六维只能"回填口径"，且模板里**硬编码的 `来自用研报告` / `留存率 92%` 等字样必须改成数据驱动**，否则页面会宣称一个并不存在的数据源。定位图 `images: []` 会自动落「暂无用研定位图」空态，可放心留空；细分满意度分布 `dist` 用 `[满意%,0,0,不满意%]` + `distLabels: ['满意','—','—','不满意']`，比编造四档分布诚实。
5. **jsdom 烟测的测试侧坑（最容易误判为产品 bug）**：
   - 筛选下拉的**状态会跨小节泄漏**（`switchView` 不重置 `#libDim` 等原生 select）→ 每个小节开头显式 reset，否则后续所有计数都被上一个筛选污染。
   - 空分区会渲染一行 `<tr><td colspan=7>无匹配记录</td>` 占位 → **不能用 `tr` 计数**，要用 `tr .t-title` 只数真实行。
   - 提炼条目卡的 `count` 与数据洞察的版本统计卡口径不同（含/不含次级），断言时别混用。
   - 断言前若刚写入数据，先 `switchView` 再数节点——DOM 是懒渲染的，上一个小节留下的 DOM 是**陈旧**的。
   - 封面卡片/记录卡**没有 class**：用 `#myCount` 文本、`[data-act="supplement"]`、`#painList [data-act="detail"][data-topic=…]` 这类语义属性做选择器，别猜 `.my-item`。
   - 标签选择器渲染的是 `.dp` 而不是 `.dim-chip`，两者都在 CSS 里，选错会得到 0。

### 数据源更新重同步（高频复用）
重新解析 → 富化（检查周映射/版本阈值是否要扩档）→ **保留旧 JSON 的分析类字段**，覆盖流水字段 → 重新注入 → 烟测 → 重新部署。模板里硬编码的周期映射表，扩档时所有出现处都要同步改。

## 示例

### 示例 1 · 从问题台账 + 会议纪要搭建工作台
输入：`问题台账.xlsx`（240 行：编号/内容/提出时间/解决方案/负责人/优先级/完成状态）+ 周会纪要 docx + 版本总结 docx。
做法：zipfile 解析 → 富化（12 个分类桶、`已完成→已解决`、W1–W10 周映射）→ kb_data.json → 七板块模板。仪表盘把 240 条聚类成 11 类通用性条目（如"武器手感缺乏统一调优标准，50 条"），30 条一次性微调归入关联分析库折叠。
产出：自包含 HTML + 固定 URL 静态站。

### 示例 2 · 每周数据源更新的低成本重同步
输入：同一 xlsx 更新（190→220→240 条），出现新的一周。
做法：重跑解析+富化；周映射从 W9 扩到 W10（模板里 weekOf/趋势图/周选择器三处硬编码同步改）；旧 JSON 的 projectIssues/topics/dimensions 原样保留；重新注入 → 烟测（断言新条目数 + 新周次）→ 重新部署同一目录，URL 不变。

### 示例 3 · 用研究六维标签改造全站口径
输入：`用研测试报告.docx`（含六维感受分析、满意率、8 条建议、4 张界面截图）。
做法：建 `dimensions[]`（定义/满意率/分布/得分/亮点/不足/建议）；条目按关键词优先级规则打 `dims[]`（多标签 ≤2）；图谱轴心改为六维并着色；数据洞察把"分类 TOP"换成"六维分布"；问题库加标签筛选；提交表单加标签必填多选；项目提炼新增六维卡 + 定位图（4 张截图压缩内嵌 + 18 个百分比坐标标签）+ 报告要点。
产出：四处口径同源、标签可跳转联动的完整体系。

### 示例 4 · 按公司方法论改造总结条目结构
输入：方法论要求"正确的目标 → KSF → 解决方案 → 复盘反思"四段式。
做法：条目补 `goal/ksf[]/review`；提交表单改四段式分组（KSF 用 textarea 每行一条，提交时 `split('\n')`）；时间轴卡片加"🎯目标摘要 + 🔑KSF N 项"；详情弹窗四段式展示；AI 接口字段说明同步更新。

## 边界

1. 不搭后端：产出纯前端静态站，提交记录只存在访问者本地浏览器，不跨设备同步；要共享须另接接口（AI 接入板块已预留 endpoint）。另：截图内嵌会让页面变大（本示例：占位图约 64KB base64 → HTML 约 350KB），超过 5 张图要评估改为外链。
2. 不手改生成后的 HTML 数据：任何修正回到数据源或 kb_data.json 重跑管线。
3. 不引 CDN/图表库：图表用内联 SVG/Canvas，保证 file:// 双击可开、部署零依赖。
4. 分类/标签的**规则**可以代拟，但阈值与兜底策略必须提示用户复核（关键词错配会导致整桶归错）。
5. 会话间模板可能被外部修改：动手前先 grep 检查关键函数/字段现状，不要凭记忆假设结构。
6. 个人目录文件只读+新增，不删除/移动；部署目录固定用项目内 `.workbuddy/deploy/`。
7. 周期映射与版本阈值是硬编码妥协：换项目必须重设，扩档必须全处同步改。
8. 定位图标签是**人工标坐标**：每张图标签 ≥4 个时成品必须截图核对遮挡，不允许只靠数值推断。
