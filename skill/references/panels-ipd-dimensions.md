## 一、七个板块（与网站导航 1:1）

| # | 导航（分组） | 视图 id | 一句话功能 |
|---|---|---|---|
| 1 | 🎯 项目提炼（核心） | `view-insight` | 全项目**结论层**：六维标签体系 + 通用性总结条目 + 用研定位图 + 报告要点 |
| 2 | 🕐 项目问题时间轴（核心） | `view-timeline` | 项目级问题按时间与四段式沉淀，可被提炼/标签反向定位 |
| 3 | 📝 项目问题提交（核心） | `view-daily` | 问题的**唯一录入入口**（含六维标签、可标未解决后补交） |
| 4 | 🗓️ 每周问题总览（过程） | `view-weekly` | 按周聚合问题与周会纪要，形成过程台账 |
| 5 | 🕸️ 问题方案图谱（过程） | `view-graph` | 以六维为轴心的关系网络，看清问题与负责人/方案的连接 |
| 6 | 📊 数据洞察（综合） | `view-dashboard` | 全量明细与统计（统计卡 + 版本概览 + 状态分布 + 六维分布 + 三层问题库） |
| 7 | 🤖 AI 接入接口（综合） | `view-ai` | 桥接接口与配置，供 AI 读写知识、自动更新 |

### 各板块内容构成与关键交互

**1. 项目提炼 `view-insight`**（默认首屏）
- IPD 阶段定位横幅（阶段链路 + KSF 重点）
- 4 张提炼统计卡：衡量标签体系 6 维 / 已覆盖问题明细 / 关联项目问题 / 未解决（全量）
- 🏷️ 六大衡量标签体系：6 张维度卡（icon + 名称 + 满意率 + 定义 + 四段满意度分布条 + 明细/未解决/提炼条目数 + ▲亮点 ▼不足；有得分时显示得分与加权）→ 点击卡即按维度筛选提炼条目
- 🎯 通用性总结条目：P-01…P-11，每条含通用化标题、维度标签 chips、条数/未解决、规律描述、关键点、主题与负责人、「🔗 关联项目问题 N」「查看明细 →」
- 📌 用研问题定位图：4 张界面截图 + 18 个百分比坐标标签（▲亮点/▼问题），点击弹出「具体问题 + 维度定义 + 用研结论 + 改进建议」，可一键跳到该维度筛选
- 📄 用研测试报告要点：结论条 + 留存动因/流失原因 + 8 条整体建议（按维度归类、可点击筛维度）

**2. 项目问题时间轴 `view-timeline`**
- 筛选：版本（全部 / 3.0 预备 / 2.0 归档）、状态、分类；联动时顶部出现来源提示条（含「清除关联」）
- 横向时间轴：主线居中、卡片上下交替（`grid-template-rows:1fr auto 1fr` 让圆点居中）、圆点按状态着色
- 卡片内容：版本徽标 + 日期 + 来源、标题、分类/状态/严重度/KSF 数/六维标签 chips/关联提炼主题 chips、🎯目标摘要、💡方案摘要
- 点击卡片 → 四段式详情弹窗（目标 → KSF → 方案 → 复盘 + 衡量标签 + 关联提炼主题）

**3. 项目问题提交 `view-daily`**
- 表单（四段式分组）：事项标题、🎯 目标成果、🔑 KSF（每行一条）、💡 解决方案、🔄 复盘反思、分类、严重程度、提出日期、来源、**衡量标签（六维·必填·可多选）**、解决状态（未解决可后续补交）
- 右侧「我的提交记录」：卡片式列表（标题、分类/状态/严重度/KSF/**标签**、目标、方案、日期、补交/编辑/删除）
- 提交后自动进入时间轴；补交/编辑弹窗内可改标签、日期、来源

**4. 每周问题总览 `view-weekly`**
- 周次选择器：按版本分两组（📦 2.0 核心玩法·开发期 / 🔄 3.0 过渡期·下版本预备）
- 本周统计卡 + 对应周会纪要（`meet-list`）+ 分类分布 + 该周问题清单

**5. 问题方案图谱 `view-graph`**
- 工具栏：版本（默认仅 3.0 预备）、**衡量标签（六维）**、负责人、布局（力导向/径向）、重置视图、图例
- Canvas 力导向图：**六维标签节点按维度着色为轴心**，负责人节点青色、问题节点按状态着色、方案节点绿色；选定维度时轴心收窄为该单一维度
- 交互：滚轮缩放、拖拽平移/拖节点、悬停 tooltip、点击查看详情

**6. 数据洞察 `view-dashboard`**
- 统计卡：3.0 预备任务 / 已解决（含解决率）/ 2.0 版本归档 / 未解决
- 版本阶段概览（版本定位、核心原则、版本周期）
- 问题状态分布（环形图 + 图例）+ **六大衡量标签分布**（条形 + 未解决数 + 满意率口径说明）
- 问题库：筛选（状态 / 分类 / 优先级 / **衡量标签**）→ 3.0 预备主列表（展开）→ 📦 2.0 归档（折叠）→ 🗂️ 次级问题·关联分析库（折叠）；行内含问题标题 + 六维标签 chips

**7. AI 接入接口 `view-ai`**
- 说明横幅 + 能力徽标；AI 服务配置（endpoint / apiKey / model + 测试连接）；桥接对象一览（`window.KnowledgeBaseAI` 方法表）；接入示例代码

### 板块之间的关系（数据流）

```
[项目问题提交] ──录入(含六维标签)──▶ [项目问题时间轴] ──按主题/维度关联──▶ [项目提炼]
        │                                  ▲                                │
        │                                  └──── 反向定位(高亮) ─────────────┘
        │                                                                   │
        └──────────────▶ [每周问题总览]（按周聚合）                          │
                                            │                               │
[数据洞察] ◀── 全量明细 + 六维分布 ──────────┘                               │
     ▲                                                                      │
     └──────── 查看明细（按主题筛选）+ 图谱按维度筛选 ◀───────────────────────┘
                                   [AI 接入接口] 可读写以上全部数据
```

**联动规则（成品已实现）**：
- 提炼条目「🔗 关联项目问题 N」→ 时间轴仅显示该主题关联的问题 + 顶部来源提示条
- 时间轴卡片的「🎯 提炼主题」chip / 详情弹窗 → 跳回提炼并高亮该条目
- 时间轴卡片的六维 chip / 定位图标签 / 报告建议 / 维度卡 → 提炼板块按该维度筛选
- 提炼条目「查看明细 →」→ 数据洞察问题库按主题筛选
- 导航切换会重置主题与维度筛选（保证每次进入都是全量视角）

## 二、板块 × IPD 体系环节

IPD 链路（成品横幅原文）：**概念 ✓ → 立项 ✓ → 核心玩法 ✓ → 核心功能 ✓ → 全功能 ✓（2.0 核心玩法已冻结）→ 过渡期·当前 → 下版本 概念/立项**

| 板块 | 对应 IPD 环节 | 在流程中的位置与作用 |
|---|---|---|
| 📝 项目问题提交 | **开发执行 · 问题登记** | 全流程的**入口**。开发/跑测期把问题连同目标、KSF、方案、复盘与六维标签一次性登记，形成可追溯的原始台账 |
| 🕐 项目问题时间轴 | **开发执行 · 问题闭环跟踪** | 承上启下。把零散问题按时间与主题串成项目级叙事，供周会/阶段评审追踪「提出→方案→复盘」是否闭合 |
| 🗓️ 每周问题总览 | **阶段评审 · 过程度量** | 周节奏的检查点。以周为单位对齐会议纪要与问题分布，用于进度/风险跟踪 |
| 🕸️ 问题方案图谱 | **技术/方案评审 · 决策支持** | 评审辅助。以六维为轴把问题、负责人、方案连成网络，识别「集中爆发点」与「责任分布」，支撑排期取舍 |
| 📊 数据洞察 | **验证 · 数据决策** | 度量层。承载用研/测试数据的统计口径（状态、六维、版本分区），用数据支撑「是否达标、是否收敛」的判断 |
| 🎯 项目提炼 | **复盘 · 经验沉淀 → 下版本概念输入** | 结论层。把全周期问题压缩成通用性条目并标注六维，结合用研报告结论输出下版本的改进输入（对应 IPD 的复盘评审与 Charter 输入） |
| 🤖 AI 接入接口 | **贯穿全阶段 · 自动化基座** | 基础设施。让上述各环节的数据可被自动读写、自动补全，减少人工搬运 |

> 位置判断口诀：**提交=入口，时间轴=过程，周总览=节奏，图谱=评审，数据洞察=度量，提炼=结论与下一步**。

| 六大要素 | 定义 | 主要对应 IPD 环节 | 承载板块（谁展示 / 谁录入 / 谁统计） | 当前用研结果 |

| ⏱ 时间成本 | 单局时长、节奏与时间节点提示的合理性 | **全功能 → 过渡期**（体验收敛、时长节奏） | 同上四类板块 | 满意率 91%(31/34)，不满意 9%(3/34) |

**三条硬性对应关系（复现时必须成立）**
1. **口径同源**：图谱轴心、数据洞察分布、问题库筛选、提交表单选项**四处都由数据层 `dimensions[]` 生成**，不存在第二份标签清单。任一维度的「筛选结果条数」必须等于该维度的 `itemCount`。
2. **标签必落到具体问题**：维度卡必须写明该维度的具体问题（亮点/不足各一句），提炼条目必须带维度标签且条目内容是具体问题而非仅标签；定位图标签必须同时给出「具体问题所在」。
3. **IPD 定位唯一**：每个板块在横幅链路中有且只有一个「当前所处」标注（成品当前为**过渡期**），提炼板块作为结论层同时承担「复盘」与「下版本概念输入」两个相邻环节。
