# 多项目工作台

项目负责人继续维护原来的 Excel 或在线表格，导出后上传工作台。平台统一存储问题数据，为每个项目生成概览、问题明细、时间轴和周总览。新项目通过网页创建，无需复制代码或重新部署。

当前版本适合内部试点：一位或几位管理员维护导入，团队通过项目独立的只读链接查看。原有 `workbench/` 静态示例完整保留，不自动导入示例数据。

## 本地启动

需要 Python 3.11 或更新版本。Windows 双击仓库根目录的 `启动工作台.cmd`，首次启动会创建虚拟环境并安装固定版本的 openpyxl，需要能访问 Python 包源。启动窗口显示本机管理口令，浏览器打开 `http://127.0.0.1:8765`。

也可以手动运行：

```powershell
cd platform
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python server.py
```

首次启动会生成 `platform/data/admin.key`，在登录页输入文件内的管理口令。数据库为 `platform/data/workbench.sqlite3`；数据和口令均已排除在 Git 之外。可通过 `WORKBENCH_ADMIN_KEY` 指定至少 16 字符的口令，通过 `WORKBENCH_DATA` 指定数据目录。

本机服务只监听 `127.0.0.1`，同事无法通过此地址访问。不要将本机链接当作团队部署链接。

手动前台启动用 Ctrl+C 停止。启动脚本会把后台进程号写入数据目录 `server.pid`；停止时先在任务管理器核对该 PID 对应本工作台的 Python 进程再结束，避免 PID 重用误停其他程序。

## 团队部署

仓库根目录提供 Docker Compose：

1. 将 `.env.example` 复制为 `.env`，设置独立的 `WORKBENCH_ADMIN_KEY`。
2. 执行 `docker compose up -d --build`。
3. 在团队服务器反向代理后配置 HTTPS 域名，将流量代理到本机 8765 端口，并保留原 Host。启用 HTTPS 时设 `WORKBENCH_SECURE_COOKIE=1` 后重启容器。
4. 在代理上设置请求体上限至少 15 MB，限制访问范围和请求速率，保留请求超时。分享 URL 含访问凭证，避免将完整路径记录到外部日志服务。

服务使用 Python 标准库 HTTP 服务和 SQLite，单实例运行；Compose 命名卷保存数据，更新容器不会丢失项目。不要执行 `docker compose down -v`，这会删除数据卷。该版本未实现企业 SSO、管理员个人账号、细粒度成员授权或多实例水平扩展。不要绕过反向代理直接开放到公网。

## 导入流程与数据规则

1. 创建项目，填写起始日期、标签和可选版本规则。
2. 上传 `.xlsx` 或 `.csv`。Excel 可选择工作表；第一行必须是非空、唯一列名，不支持合并表头。限制 10 MB、20,000 数据行、100 列。
3. 确认字段映射。问题编号和问题内容必填；成功导入后记住映射。
4. 检查预览中的新增、更新、无变化与缺失保留记录。存在错误时整个批次不会写入。
5. 确认导入后，所有看板立即使用数据库内的数据。原始表格不会被修改。

每个项目使用一份主问题表，`项目 ID + 问题编号` 唯一标识问题。编号应长期稳定，带前导零的编号在 Excel 中需存成文本。不能把编号相同的不同问题从多个表直接混合导入。

同编号按映射后的源表内容更新；未映射字段会重置为默认值，预览会显示字段变化。表中缺少的现有问题保留，避免误删历史。关闭问题请在源表标记已解决；本版不提供自动删除和网页修改问题。

默认值：状态未解决、负责人未分配、分类未分类、优先级未标注。未知状态、重复编号、无效日期、未配置标签会阻止导入。多个标签可用逗号、分号、顿号或竖线分隔。Excel 公式拒绝导入，请先粘贴为值，避免过期缓存造成数字错误。CSV 支持 UTF-8 和 GB18030。

每次导入保存完整的前后数据快照。预览绑定项目数据版本，其他管理员导入或修改配置后，旧预览将失效，必须重新预览。进程重启或超过 30 分钟未确认也需要重新上传。原始上传文件仅暂存在内存，不写入持久化数据目录。

## 统计口径

- 总问题数为数据库当前全部记录，包括这次文件中缺少而保留的问题。
- 未闭环包含未解决、进行中和待验证；解决率仅以已解决计算。
- 多标签问题会计入多个标签，维度计数之和可能大于总问题数。不生成满意率或用研评分。
- 周次从项目起始日期算起，每 7 天一周；统计按提出日期分组，状态是当前状态，不代表当周历史解决率。
- 源表版本优先；版本为空时按提出日期与配置的版本起始日期推导。无日期或早于最早版本显示未划分。
- 时间轴展示问题提出日期，当前未实现状态变更事件时间轴、会议纪要或用研结论。

## 公司 AI 知识库接入边界

设置页生成项目只读链接，同时生成 `GET /api/share/<token>` JSON 地址。凭证随机生成，数据库仅保存哈希。新生成链接或撤销分享会使旧凭证失效。

响应包含 `project` 和 `items`，每条问题具有 `id/title/owner/status/date/solution/priority/category/tags/version/resolvedAt/effectiveVersion/week/weekIndex`。接口与看板同源，供公司知识库服务器后续读取；浏览器跨域访问未开放。持有链接即可读取该项目全部数据，分享前确认接收者有权查看。

尚未连接公司 AI 知识库；本版不新增策划问题录入、不调用模型、不配置模型密钥、不解析 Word 报告、不自动监控在线表格。等明确公司知识库和现有表格系统的接口后，在服务器增加连接器，并复用现有的校验和批次导入逻辑。

## 备份和恢复

SQLite 使用 WAL。停止服务后备份整个数据目录（包括数据库、WAL/SHM 文件和管理口令），不要在运行时只复制主数据库文件。需要不停机备份时通过 SQLite backup API 生成一致快照。

本版保存导入前后快照用于追溯，但没有网页回滚按钮。发现错误可修正源表重新导入；因新增错误编号需要完全回滚时，先备份当前目录，再由管理员离线恢复数据库。不要直接编辑在线数据库。

## 测试

```powershell
cd platform
python -m unittest discover -s tests -v
```

测试使用独立临时数据库，覆盖导入幂等、更新与缺失保留、批次原子性、并发预览冲突、项目隔离、日期规则、CSV/Excel 解析、身份验证和分享撤销。浏览器端验收脚本为 `tests/browser-smoke.cjs`，需要 Playwright 和本地 Chromium，具体运行方式见脚本头部。
