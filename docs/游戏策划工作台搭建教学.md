## 二、先建立三套对应的体系（这是工作台的骨架）

### 2.1 七大板块（与导航一一对应）

| 导航分组 | 板块 | 一句话功能 | 内容构成 |
|---|---|---|---|
| **核心** | 🎯 项目提炼 | 全项目**结论层** | IPD 阶段横幅 · 4 张提炼统计卡 · 六大衡量标签体系卡 · 通用性总结条目 · 用研问题定位图 · 用研报告要点 |
| 核心 | 🕐 项目问题时间轴 | 项目级问题与方案沉淀 | 版本/状态/分类筛选 · 横向时间轴（卡片上下交替）· 四段式详情弹窗 |
| 核心 | 📝 项目问题提交 | 问题**唯一录入入口** | 四段式表单 + 六维标签（必填多选）+ 解决状态 · 我的提交记录 |
| **过程** | 🗓️ 每周问题总览 | 过程台账 | 周次选择（按版本分组）· 本周统计 · 周会纪要 · 分类分布 · 问题清单 |
| 过程 | 🕸️ 问题方案图谱 | 关系网络与决策支持 | 版本/标签/负责人/布局筛选 · Canvas 力导向图（六维为轴心）· 图例 |
| **综合** | 📊 数据洞察 | 全量度量 | 4 张统计卡 · 版本阶段概览 · 状态分布 · 六维分布 · 三层问题库 + 四类筛选 |
| 综合 | 🤖 AI 接入接口 | 自动化基座 | 接口说明 · 服务配置 · 桥接方法一览 · 接入示例 |

**板块之间的关系（数据流）**

```
[问题提交]──录入(含六维标签)──▶[问题时间轴]──按主题/维度关联──▶[项目提炼]
      │                              ▲                            │
      │                              └──反向定位(高亮)────────────┘
      └────────▶[每周总览]（按周聚合）                              │
[数据洞察]◀──全量明细 + 六维分布 ───────────────────────────────────┘
      ▲                                                            │
      └─── 查看明细（按主题筛）+ 图谱按维度筛 ◀────────────────────┘
                        [AI 接入接口] 可读写以上全部数据
```

### 2.2 板块 ↔ IPD 体系环节

IPD 链路：**概念 ✓ → 立项 ✓ → 核心玩法 ✓ → 核心功能 ✓ → 全功能 ✓ → 过渡期·当前 → 下版本 概念/立项**

| 板块 | 对应 IPD 环节 | 位置与作用 |
|---|---|---|
| 📝 项目问题提交 | 开发执行 · 问题登记 | **入口**。把问题连同目标/KSF/方案/复盘与标签一次登记 |
| 🕐 项目问题时间轴 | 开发执行 · 问题闭环跟踪 | **过程**。按时间与主题串成项目级叙事，供评审追踪是否闭合 |
| 🗓️ 每周问题总览 | 阶段评审 · 过程度量 | **节奏**。周检查点，对齐纪要与问题分布 |
| 🕸️ 问题方案图谱 | 技术/方案评审 · 决策支持 | **评审**。以六维为轴看清问题—负责人—方案连接，识别爆发点 |
| 📊 数据洞察 | 验证 · 数据决策 | **度量**。承载统计口径与达标判断 |
| 🎯 项目提炼 | 复盘 · 经验沉淀 → 下版本概念输入 | **结论**。压缩全周期问题 + 用研结论，输出改进输入 |
| 🤖 AI 接入接口 | 贯穿全阶段 · 自动化基座 | **底座**。让数据可被自动读写与补全 |

> 口诀：**提交=入口，时间轴=过程，周总览=节奏，图谱=评审，数据洞察=度量，提炼=结论与下一步**。

### 2.3 六大要素 ↔ 板块 ↔ IPD 环节

六大要素（衡量标签）：**新鲜感 / 目标感 / 成长感 / 乐趣性 / 社交感 / 时间成本**

| 六大要素 | 定义 | 主要对应 IPD 环节 | 承载板块 | 示例用研结果 |
|---|---|---|---|---|
| ✨ 新鲜感 | 题材差异化与机制创新带来的新奇体验 | 概念 / 立项（差异化卖点） | 提炼（展示）· 数据洞察（统计）· 图谱（轴心）· 提交（录入） | 满意率 100%，得分 1.18（加权 1.76） |
| 🎯 目标感 | 局内搜、打、撤多目标的清晰度与长线养成指向 | 核心玩法（循环目标） | 同上四类 | 满意率 97%，得分 1.00（加权 1.59） |
| 📈 成长感 | 局外打造与局内增益双线的成长可见度与挫败控制 | 核心功能（养成线） | 同上四类 | 满意率 97% |
| 🎮 乐趣性 | 核心玩法基底、战斗反馈与操作手感带来的乐趣 | 核心玩法 → 全功能（手感打磨） | 同上四类 | 满意率 100%（评价最高） |
| 🤝 社交感 | 组队协作、沟通机制与团队配合的体验 | 核心功能（组队与沟通） | 同上四类 | 满意率 91% |
| ⏱ 时间成本 | 单局时长、节奏与时间节点提示的合理性 | 全功能 → 过渡期（体验收敛） | 同上四类 | 满意率 91% |

**三条硬性对应关系（务必保持）**
1. **口径同源**：图谱轴心、数据洞察分布、问题库筛选、提交表单选项——四处都由同一份标签定义生成；任一处改了，四处一起改。
2. **标签落到具体问题**：每张标签卡要写明该维度的具体问题（亮点/不足各一句）；总结条目与定位图标签都要给出「具体问题所在」，不能只贴标签。
3. **IPD 定位唯一**：横幅上只有一个「当前」标注；项目提炼同时承担「复盘」与「下版本概念输入」。

| 状态色 | 绿 `#16a34a` 已解决 / 橙 `#f59e0b` 待验证 / 蓝 `#3b82f6` 进行中 / 红 `#ef4444` 未解决 | 状态 chip 与圆点 |
| 侧边栏 | `#111a33` | 深色导航底 |
| 六大标签 | 新鲜感 `#8b5cf6` / 目标感 `#3b82f6` / 成长感 `#16a34a` / 乐趣性 `#ef4444` / 社交感 `#0d9488` / 时间成本 `#f59e0b` | 标签卡色条、标签 chip、图谱轴心、分布条 |

### 3.2 布局与字体

- 侧边栏固定 **236px**，内容区自适应；顶栏高 **60px**；内容区内边距 **24px**。
- 卡片圆角 **14px**，阴影 `0 1px 3px rgba(23,32,74,.06), 0 6px 18px rgba(23,32,74,.05)`；hover 上浮并加深阴影。
- 字体栈：系统中文优先（`-apple-system / PingFang SC / Microsoft YaHei`），基准 **14px / 行高 1.6**；统计数字 30px 加粗。
- 栅格间距 **16px**，四列统计卡在大屏以下依次降为 2 列、1 列（断点 1100px / 900px / 820px）。

### 3.3 关键组件样式

| 组件 | 规格 |
|---|---|
| 导航项 | 圆角 10px、13.5px、灰蓝字；hover 白色 6% 底；选中主色渐变 + 投影 |
| 统计卡 | 左侧 4px 色条 + 30px 数值 + 右上淡图标 + 说明行 |
| 状态/优先级 chip | 圆角 20px、12px、浅底同色字 |
| 表格 | 表头吸顶灰底、行 hover 变色、外层圆角 12px 容器 |
| IPD 横幅 | 深色渐变 `#111a33 → #25356e` + 阶段胶囊（已完成绿字 / 当前主色实底） |
| 标签卡 | 左侧 4px 标签色条 + 满意率胶囊 + 四段满意度分布条 + 明细/未解决/条目数 + ▲亮点 ▼不足 |
| 总结条目卡 | 编号块 + 通用化标题 + 标签 chips + 规律描述 + 关键点 + 关联按钮 |

| 图谱画布 | 高 640px、22px 点阵网格底、抓手光标 |

> **照抄指令**
> 根据文件夹里的资料，开发一个 HTML 项目工作台，要求包含七大板块：项目提炼、项目问题时间轴、项目问题提交、每周问题总览、问题方案图谱、数据洞察、AI 接入接口。以【新鲜感、目标感、成长感、乐趣性、社交感、时间成本】六项作为问题衡量标签，主要问题分类也以此为依据，并且每项分类下要写明具体问题所在。项目提炼板块要标注每个问题所属的六维度分类。用【目标→KSF→解决方案→复盘】四段式组织总结条目。

> ⚠️ AI 生成前若向你确认假设，**逐条回答**；这一步的确认成本远低于返工成本。

### 第 2 步 · 让 AI 生成初版

- [ ] 提交表单能选标签、能标「未解决」并后续补交
- [ ] 图谱能拖动缩放，轴心是六大标签

## 五、常见问题（FAQ）

**Q1 表格列名和示例不同，可以吗？**
可以。AI 会列出识别到的列名映射供你确认；建议至少包含「问题内容 / 负责人 / 完成状态」三列。

**Q2 问题被归到错误的标签下？**
直接说明哪类问题应归哪个标签。若某维度总是误吸条目，通常是关键词太宽（如"显示"会误伤大量条目），要求收窄。

**Q3 六大标签的满意率和得分从哪来？**
来自用研/测试报告的对应维度数据（分维度感受分析、满意率、评分）。若报告缺失某维度数据，界面会显示"—"，不要编造。

**Q4 定位图的标签位置不对/互相遮挡？**
标签是百分比坐标人工标注的，直接指出："【某张图】的【某标签】应移到【左/右/上/下】"；每张图 ≥4 个标签时成品必须截图核对。

**Q5 筛选下拉选了没反应？**
历史高频 bug，多为监听未绑定。直接说"问题库的筛选没反应，修复一下"，AI 修完会自动回归测试。

**Q6 周数/版本划分不对？**
周映射与版本阈值是写死的。跨周后说"出现新的一周，扩展周映射"；节点变了说"版本划分改为以【某日】为界"。

**Q7 同事改了数据会互相覆盖吗？**
不会覆盖，但互相看不见——静态页的提交记录各自存在本机浏览器。要共享需接后端接口（AI 接入板块已预留 endpoint）。

**Q8 换一个新项目能复用吗？**
能。新文件夹 + 新资料，用第 1 步指令；AI 复用整套骨架与样式，只需重新确认分类、六维标签、版本划分。从几天缩短到几十分钟。

**Q9 页面体积会不会太大？**
内嵌截图会变大（4 张约 0.5MB）。超过 5 张图建议改为外链或更多压缩。

## 六、验收检查清单（每次生成/同步后过一遍）

**体系对应**
- [ ] 七个板块与导航三组齐全，默认落在「项目提炼」
- [ ] IPD 横幅阶段链完整，且只有一个「当前」标注
- [ ] 六大标签在提炼/图谱/数据洞察/提交四处口径一致、颜色一致
- [ ] 每张标签卡写明该维度的具体问题；总结条目与定位图标签都给出「具体问题」

**数据正确性**
- [ ] 总条目数 = 表格实际行数；各状态数量与表格一致
- [ ] 抽查 3 条的标签、负责人、解决方案显示正确
- [ ] 维度筛选后的条数 = 该维度应有条数；图谱全量 6 个轴心、选定后 1 个

**功能完整性**
- [ ] 提交「未解决」后能补交方案并转为已解决；标签必填可多选且能回显修改
- [ ] 每个筛选控件选择后列表立即变化
- [ ] 三层问题库（当前版本展开 / 旧版本折叠 / 关联分析库折叠）可展开
- [ ] 提炼「关联项目问题」→ 时间轴筛选 + 来源提示条；时间轴标签 → 回提炼并高亮
- [ ] 定位图标签点击可看详情并跳转维度筛选

**交付状态**
- [ ] 本地 HTML 双击可打开
- [ ] 线上链接可访问且数字与本地一致
- [ ] 本次更新后已重新部署

### 8.1 开工清单（全部免费/已有）

| 工具 | 用途 | 你要做的 |
| --- | --- | --- |
| WorkBuddy | 替你完成解析、生成、测试、部署 | 打开对话，按模板下指令 |
| 一个项目文件夹 | 放资料与产物 | 桌面新建，如 `XX项目知识库` |
| 项目资料 | 工作台的内容来源 | 把文件放进该文件夹 |

资料要求：问题跟踪表（Excel）建议列为 `编号 / 问题内容 / 提出时间 / 解决方案 / 负责人 / 优先级 / 完成状态`，列名不同也可以，AI 会先与你确认；会议纪要与版本总结为可选，有则可自动生成每周总览与版本定位。

### 8.2 五步走检查点

1. 明确需求（10 分钟）：想清数据源、板块、分类、分层、版本 5 件事，一次性告诉 AI，并把【】里的内容换成自己的。
2. 让 AI 生成初版：AI 自动完成解析 → 分类 → 生成网页 → 自测 → 打开预览；你重点看 4 处，即总条目数与表格行数是否一致、分类归得对不对、提交能否选"未解决"并补交、图谱能否拖动缩放。
3. 迭代打磨：用大白话提需求，可多轮。
4. 生成外部分享链接：任何人浏览器可直接打开；管理入口为「设置 → 数据管理 → 我发布的应用」。
5. 日常同步：表格更新后说"已更新，同步工作台"，AI 重新解析并保留此前提炼内容，链接不变。

### 8.3 常用迭代指令（照抄）

| 想改什么 | 照抄指令 |
| --- | --- |
| 改提交内容 | "每日提交改成提交分析得到的项目问题及解决方案，这些问题用横向时间轴单独开一个板块展示" |
| 加筛选 | "图谱增加筛选：可以筛某一个功能分类或单个负责人，【某人】和【某小名】是同一个人不要分开" |
| 压缩显示 | "仪表盘对问题分类后总结显示，重复出现的问题压缩成关键疑难点，不紧急的折叠到问题库的次级模块" |
| 分版本 | "注意【某日期之前】是已结束版本要折叠归档，【某日期之后】是当前版本要优先显示，问题库、图谱、时间轴、每周总览都做这个区分" |
| 套公司方法论 | "按【目标 → 关键成功要素 → 解决方案 → 复盘反思】重新梳理解决方案的措辞和提交表单" |
| 改文案 | "把不正式的描述改掉，比如'压缩后问题条目'改成'通用性总结条目'，不要解释性副标题" |

### 8.4 高频问答速查

- 表格列名不一样怎么办：AI 会列出识别到的列名映射供你确认，建议至少含问题内容、负责人、完成状态三列。
- 分类归错了怎么办：直接说"含【某关键词】的问题应归到【某类】"；若某类总被归错，通常是关键词太宽（如"显示"误伤大量条目）。
- 负责人写法不统一怎么办：告诉 AI 哪些名字是同一人，它会做别名合并；首次生成后先检查负责人名单。
- 筛选下拉选了没反应：历史高频 bug，说"筛选没反应，修复一下"，AI 会自动回归测试。
- 周数/版本划分不对：周映射与版本阈值是写死的，跨周说"扩展周映射"，改节点说"以【某日】为界"。
- 同事改了数据会互相覆盖吗：不会覆盖但互相看不见，静态页记录存在各自浏览器；要共享需接后端接口（AI 接入板块已预留）。
- 换新项目能复用吗：能。新文件夹加新资料，用第 1 步指令，AI 复用整套骨架与样式，从几天缩短到几十分钟。
- 能不能跳过 AI 的假设确认：不建议。分类标准、分层标准、版本分界这三项错了会全部返工，花 5 分钟确认可省 2 小时。

### 8.5 三类验收清单

**数据正确性**

- ☐ 总条目数 = 表格实际行数（对不上就问）
- ☐ 各状态数量与表格一致
- ☐ 抽查 3 条的分类、负责人、解决方案显示正确
- ☐ 负责人名单无重复人（别名已合并）

**功能完整性**

- ☐ 统计卡数字与条目数自洽
- ☐ 提交"未解决"后能在记录里补交方案并转为已解决
- ☐ 每个筛选控件选择后列表立即变化（逐个试）
- ☐ 折叠模块能展开收起
- ☐ 图谱能拖动、缩放、按分类与负责人筛选
- ☐ 时间轴与每周总览的版本分组正确（新版本优先）

**交付状态**

- ☐ 本地 HTML 双击可打开
- ☐ 线上链接可访问且数字与本地一致
- ☐ 本次更新后线上已重新部署

### 8.6 一页纸流程

1. 准备资料（xlsx / docx 放进文件夹）
2. 第 1 步：下指令 + 确认 AI 的假设（数据源 / 板块 / 分类 / 分层 / 版本）
3. 第 2 步：AI 生成 → 你检查 4 件事（条数 / 分类 / 提交 / 图谱）
4. 第 3 步：大白话迭代（改提交内容 / 加筛选 / 压缩显示 / 分版本 / 套方法论 / 改文案）
5. 第 4 步：部署外部分享链接
6. 第 5 步：表格更新后说"已更新，同步工作台"（链接不变，分析内容自动保留）
