# 星港计划 项目知识管理工作台（示例仓库）

> ⚠️ 本仓库为**示例 / 临时数据**版本，用于演示「项目知识管理工作台」的结构与能力。
> **不含任何真实人员姓名与真实项目问题**：问题条目、解决方案、会议纪要、体验测试结论均为合成内容；
> 4 张界面图为程序生成的占位模拟图（非真实截图）。

把项目分散资料（问题台账、会议纪要、版本总结、体验测试报告）整合成的**自包含 HTML 项目工作台**。
单文件、零依赖、双击即开，含七大板块、IPD 阶段定位与六大衡量标签体系。

---

## 一、快速查看

直接打开 `workbench/index.html`（双击即可，无需服务器、无需联网）。

## 二、仓库结构

```

    ├── SKILL.md                    # 制作流程（六章：适用场景/纪律/六步/示例/边界/自检）
    ├── TRACE_SELF_ASSESSMENT.md    # 自评（任务/角色/动作/约束/产出）

        ├── workbench.css               # 真品样式表（与成品逐字节一致）
        ├── ui-spec.md                  # UI 规格：设计令牌 / 布局 / 组件 / 动效

        └── teaching-guide.md           # 教学文档副本
```

## 三、工作台包含什么

**七大板块**（导航分「核心 / 过程 / 综合」三组）

| 分组 | 板块 | 作用 |
|---|---|---|
| 核心 | 🎯 项目提炼 | 结论层：六维标签体系 + 通用性总结条目 + 体验问题定位图 + 报告要点 |
| 核心 | 🕐 项目问题时间轴 | 项目级问题与方案按时间沉淀，四段式详情 |
| 核心 | 📝 项目问题提交 | 问题唯一录入入口（含六维标签、未解决可补交） |
| 过程 | 🗓️ 每周问题总览 | 过程台账：周次分布 + 周会纪要 |
| 过程 | 🕸️ 问题方案图谱 | 以六维为轴心的关系网络（Canvas 力导向） |
| 综合 | 📊 数据洞察 | 全量统计 + 三层层级问题库 + 四类筛选 |
| 综合 | 🤖 AI 接入接口 | 桥接接口 `window.KnowledgeBaseAI` 与配置 |

**IPD 阶段链**：概念 → 立项 → 核心玩法 → 核心功能 → 全功能 → 过渡期（当前）→ 下版本概念/立项

**六大衡量标签**（全站统一口径）：新鲜感 · 目标感 · 成长感 · 乐趣性 · 社交感 · 时间成本

## 四、如何更新数据

工作台采用「数据与模板分离」：`source/template.html` 里的 `__KB_DATA__` 会被 `source/kb_data.json`
替换后生成 `index.html`。

1. 更新 `source/kb_data.json`（或重新跑数据管线，见 `skill/SKILL.md` 步骤 2）
2. 用 JSON 替换模板中的 `__KB_DATA__` 占位符，输出为 `workbench/index.html`
3. 建议生成后跑一遍校验（`skill/SKILL.md` 步骤 6：语法检查 + jsdom 烟测 + 截图核对）

---

## 五、用这套 Skill 做新项目的工作台

`skill/` 是可直接复用的制作 Skill。把它放进 Skill 目录后用自然语言调用即可，例如：

> 按 project-workbench-builder 给我搭一个项目工作台，资料在 ./资料，衡量标签用「爽度 / 深度 / 留存」

复现一致性由 `skill/references/workbench.css`（真品样式表，与成品逐字节一致）保证。

## 六、示例数据说明

- 人员姓名、问题内容、解决方案、会议纪要、体验测试结论**全部为合成内容**，仅用于演示结构；
- 4 张界面图为**程序生成的占位模拟图**，不是任何真实产品的截图；
- 原始资料（问题台账 xlsx、版本总结 docx、体验测试报告 docx、周会纪要 docx）**未包含**在本仓库；
- `workbench/index.html` 已内嵌工作台所需的全部数据与图片，可独立运行；
- 网页上的「提交」记录保存在**每位访问者自己的浏览器**（localStorage），不会同步到仓库；
  团队共享提交数据需接入后端接口（工作台「AI 接入接口」板块已预留 endpoint）。
